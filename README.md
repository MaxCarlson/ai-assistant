# AI Assistant

This repository houses a versatile AI assistant designed to automate and manage various software engineering tasks. It features a modular architecture supporting different user interfaces and advanced agent capabilities, including task management, tool integration, and context-aware processing.

## Features

*   **Multi-Interface Support**: Interact with the AI assistant through a Command-Line Interface (CLI), a Text User Interface (TUI), or a dedicated desktop application.
*   **Autonomous Agents**: Leverage AI agents capable of understanding and executing complex tasks with minimal human intervention.
*   **Task Management**: Define, track, and manage tasks assigned to AI agents, including their goals, progress, and execution history.
*   **Tool Integration**: Agents can utilize a variety of tools to perform actions, interact with the environment, and gather information.
*   **Workspace Isolation**: Each agent task operates within its own isolated workspace, ensuring clean execution environments and preventing conflicts.
*   **Advanced Agentic Features**:
    *   **Retrieval Augmented Generation (RAG)**: Enhance agent knowledge and response generation by integrating external information sources.
    *   **Embeddings**: Utilize vector embeddings for efficient information retrieval and semantic understanding.
    *   **Code Parsing**: Agents can parse and understand code structures, enabling more intelligent code modifications and analysis.

## Project Structure

*   `src/`: Contains the core Python application logic.
    *   `agent_manager.py`: Manages the lifecycle and execution of AI agents.
    *   `task_manager.py`: Handles the creation, tracking, and state management of tasks.
    *   `tool_manager.py`: Manages the registration and invocation of tools available to agents.
    *   `workspace_manager.py`: Oversees the creation and management of isolated workspaces for tasks.
    *   `cli.py`, `cli_handler.py`: Components for the command-line interface.
    *   `desktop_app.py`: Entry point or logic for a desktop application.
    *   `termux_app.py`: Specific implementation for running the assistant within Termux environments.
    *   `tui_app.py`, `tui/`, `tui.css`, `ui.py`: Modules related to the Text User Interface.
    *   `full_features/`: Houses advanced agent capabilities such as `rag_manager.py`, `obsidian_embeddings.py`, `code_parser.py`, and different agent types (`agent_full.py`, `agent_minimal.py`, `base_agent.py`).
*   `exports/`: Stores logs and outputs generated by agent tasks, typically organized by task ID (e.g., `task_1_log.txt`).
*   `faiss_index/`: Contains FAISS index files (`index.faiss`, `index.pkl`), likely used for efficient similarity search in RAG implementations.
*   `workspaces/`: Directory where individual agent tasks execute. Each subdirectory (e.g., `1/`, `10/`) represents an isolated workspace for a specific task, containing files generated or modified by the agent during its execution.
*   `tests/`: Contains unit and integration tests for various modules, ensuring the reliability and correctness of the system.
*   `tasks.json`: A crucial file that stores metadata for all tasks, including their goals, execution history, current status, allowed tools, and the working directory for each task. This file is actively used by the task management system.
*   `SetupTreeSitter.sh`: A shell script for setting up Tree-sitter, a parsing library, which might be used for code analysis within the `code_parser.py` module.

## Usage

The AI Assistant can be interacted with through various interfaces, each offering a unique experience.

### Running the CLI

The primary way to interact with the assistant is via the command-line interface, using `src/main.py` as the entry point. The CLI supports several commands:

```bash
python src/main.py <command> [arguments]
```

**Global Options**:
*   `--debug`: Enable debug logging for agents.

**Available Commands**:

*   **`do`**: Create and start a new task.
    *   **Usage**:
        ```bash
        python src/main.py do <goal> [--from-file <file_path>] [--tools <tool1> <tool2> ...]
        ```
    *   **Arguments**:
        *   `<goal>`: The main objective or description of the task for the agent. This can be a multi-word string.
        *   `--from-file <file_path>` or `-f <file_path>`: Instead of providing the goal directly on the command line, read the task goal from the specified file. Useful for complex or lengthy task descriptions.
        *   `--tools <tool1> <tool2> ...` or `-t <tool1> <tool2> ...`: Specify a space-separated list of tools that the agent is allowed to use for this specific task. If not specified, the agent will likely have a default set of tools available. Examples of tools include `read_file`, `write_file`, `run_shell_command`, `web_search`, `run_pytest`, etc. (Refer to `src/tool_manager.py` for a comprehensive list of implemented tools).
    *   **Example**:
        ```bash
        # Create a task to write a Python script for prime numbers
        python src/main.py do "Write a Python script to find prime numbers efficiently."

        # Create a task with a goal from a file and specific tools
        echo "Refactor the authentication module to use OAuth2." > my_refactor_goal.txt
        python src/main.py do --from-file my_refactor_goal.txt --tools read_file write_file modify_file run_pytest
        ```

*   **`list`**: List all tasks.
    *   **Usage**:
        ```bash
        python src/main.py list
        ```
    *   **Description**: Displays a summary of all tasks, including their ID, current status, and a truncated version of their goal.
    *   **Example**:
        ```bash
        python src/main.py list
        # Expected output:
        # ID: 15 | Status: completed_by_agent | Goal: i wamt you to go back through the script and refactor it suoer agressively...
        # ID: 16 | Status: pending_input | Goal: write a oython script to effeciently find prime numbers whike utilizing...
        ```

*   **`view`**: Launch the TUI to view all tasks.
    *   **Usage**:
        ```bash
        python src/main.py view
        ```
    *   **Description**: Switches the interface to the Text User Interface (TUI) mode, providing a more interactive way to monitor and manage tasks.

*   **`chat`**: Start the interactive chat mode.
    *   **Usage**:
        ```bash
        python src/main.py chat [--model <model_name>] [--sandbox] [--agent] [--temperature <value>] [--top-p <value>] [--top-k <value>] [--max-output-tokens <value>] [--grounding] [--code-execution]
        ```
    *   **Description**: Initiates a conversational chat session with the AI assistant. This mode is designed for direct interaction and can be configured with various parameters to control the agent's behavior.
    *   **Arguments**:
        *   `--model <model_name>`: Specify the AI model to use for the chat session (e.g., `gemini-2.5-pro`). Default is `gemini-2.5-pro`.
        *   `--sandbox`: Enable sandbox mode for code execution, providing a more secure environment.
        *   `--agent`: Run in agent mode. In this mode, the assistant might behave more autonomously, attempting to complete tasks based on the conversation.
        *   `--temperature <value>`: Control the randomness of the model's output. A higher value (e.g., 0.7) makes the output more random, while a lower value (e.g., 0.2) makes it more deterministic. Default is `0.7`.
        *   `--top-p <value>`: Control the diversity of the model's output by sampling from the most probable tokens whose cumulative probability exceeds `top-p`. Default is `1.0`.
        *   `--top-k <value>`: Limit the model's output to the `top-k` most probable tokens. Default is `40`.
        *   `--max-output-tokens <value>`: Set the maximum number of tokens the model can generate in a single response. Default is `1024`.
        *   `--grounding`: Enable Google Search grounding, allowing the agent to use web search results to inform its responses.
        *   `--code-execution`: Enable code execution capabilities within the chat, allowing the agent to run and test code snippets.
    *   **Example**:
        ```bash
        # Start a basic chat session
        python src/main.py chat

        # Start a chat session with a specific model and sandbox enabled
        python src/main.py chat --model gemini-1.5-flash --sandbox

        # Start a chat session in agent mode with grounding and code execution
        python src/main.py chat --agent --grounding --code-execution
        ```

### Interacting with Agents

Agents are the core of the AI Assistant's automation capabilities. They are designed to take on specific tasks and work towards their completion autonomously.

**Agent Lifecycle and Behavior**:
When an agent is assigned a task, it typically follows an iterative "thought-tool-result" loop:
1.  **Thought**: The agent analyzes the task goal, its current state, and available information to formulate a plan or decide on the next action.
2.  **Tool Call**: Based on its thought process, the agent selects and executes one or more `allowed_tools`.
3.  **Tool Result**: The agent receives the output or result from the executed tool, which it then uses to inform its next "thought."

This loop continues until the task is completed, fails, or requires user intervention. The entire history of this loop, including the agent's thoughts and tool calls, is logged in `tasks.json` and detailed log files in `exports/`.

**Tools and Abilities**:
Agents are equipped with a set of tools that allow them to interact with the environment and perform various operations. The specific tools available to an agent for a given task are defined in the `allowed_tools` list within `tasks.json`. Common tool categories include:

*   **File System Operations**:
    *   `read_file`: Read the content of a file.
    *   `write_file`: Create a new file or overwrite an existing one.
    *   `modify_file` (or `replace`): Modify specific parts of a file.
    *   `list_directory`: List contents of a directory.
    *   `search_file_content`: Search for patterns within file contents.
*   **Code Execution**:
    *   `execute_python_code`: Run Python code snippets or files.
    *   `run_shell_command`: Execute arbitrary shell commands (with appropriate safety checks).
    *   `run_pytest`: Execute Python tests using `pytest`.
*   **Information Gathering**:
    *   `web_search`: Perform web searches to gather information.
    *   `web_fetch`: Fetch content from URLs.
*   **Task Management**:
    *   `task_complete`: Mark a task as complete.
    *   `request_user_input`: Request clarification or input from the user.

The `tool_manager.py` module is responsible for registering and dispatching these tools, making them available to the agents. The capabilities of an agent are directly tied to the tools it has access to and its ability to strategically use them to achieve its goals.

### Task Management

The `task_manager.py` module is responsible for the lifecycle of tasks. It handles:

*   **Task Definition**: Defining a task with a clear goal.
*   **State Management**: Tracking the current `status` of a task (e.g., `pending`, `in_progress`, `completed_by_agent`, `failed`).
*   **History Logging**: Recording every step an agent takes, including its internal `thought` process and `tool_call`s. This history is crucial for debugging and understanding agent behavior.
*   **Tool Allocation**: Specifying which `allowed_tools` an agent can use for a particular task.
*   **Workspace Allocation**: Assigning an isolated `working_dir` within `workspaces/` for each task to prevent interference between different agent runs.

While direct manipulation of `tasks.json` is not recommended, understanding its structure is key to comprehending how tasks are managed internally.
